# 仕様書 類似検索ツール — 開発記録

## 概要

車両の仕様書(Markdown形式)を対象にした、ローカル環境で完結する意味検索(セマンティック検索)ツール。
外部APIやクラウドサービスを使わず、すべて自分のPC上で動作する。

## 技術構成

- バックエンド: FastAPI
- 埋め込みベクトル生成: sentence-transformers(`paraphrase-multilingual-MiniLM-L12-v2`, 多言語対応)
- 類似度計算: numpy(コサイン類似度)
- 画面: 素のHTML/CSS/JavaScript(フレームワーク無し)

## 対象データ

- `data/<メーカー>/<車種>/.../published/<カテゴリ>/*.md` という構成のMarkdown文書
- 現在: `data/honda`, `data/subaru` 配下(282文書 / 1250チャンク)

## 実装済み機能

### 検索基盤

- Markdownの見出し単位でチャンク化し、ベクトル化(`app/ingest.py`, `app/embed.py`)
- コサイン類似度による検索ロジック(`app/search.py`)
- API(`/api/search`, `/api/stats`)と検索画面(`app/main.py`, `app/static/index.html`)

### 前後文脈の表示

検索でヒットしたチャンクの抜粋だけでなく、その前後にある文章も「前の文脈 / 該当箇所 / 後の文脈」の
3列で表示する。抜粋だけだと文脈が分からず誤読しやすい問題に対応するため。前後は同一文書内の隣接する
チャンクから取得し、文書の先頭・末尾では空欄になる。

### 同義語辞書によるクエリ拡張

`app/expansion_rules.json`に略語・表記ゆれのグループ(例: `BT` ⇔ `Bluetooth`、`CarPlay` ⇔
`Apple CarPlay` ⇔ `カープレイ`)を登録し、検索前にクエリへ言い換え語を自動的に追記する
(`app/query_expansion.py`)。辞書はJSONファイルの編集だけで調整でき、コードの変更は不要。
画面には「辞書により検索語を拡張しました」という注記を出し、何が追加されたか分かるようにしている。

辞書には、社内の用語集(略語と正式名称の対応表)の内容を反映している。

### スコアリングのバージョン管理

検索スコア(コサイン類似度)から、グレード(A/B/C/D)や「該当あり/なし」を判定する閾値を
`app/scoring.py`の`SearchPolicy`にまとめ、バージョン名(現在: `v3`)を付けて管理している。
閾値をチューニングしたいときは新しいバージョンを追加して切り替えるだけでよく、過去の設定は
消さずに残すため、いつでも前のバージョンに戻せる。

### 絞り込み軸の宣言制

`data/facets.json`で「フォルダ構成のどの階層が"メーカー"や"車種"のような絞り込み軸か」を
明示的に宣言する方式にしている。宣言の無いデータに対しては、フォルダ名から絞り込み軸を
勝手に推測せず、絞り込み機能(画面のチップ・APIパラメータ)自体を無効化する。データ構成が
変わったときに誤ったラベルや絞り込みボタンが出てしまうことを防ぐため。

### キーワード一致検索へのフォールバック

意味検索(ベクトル)は型番・固有名詞・数値のような「言い換えのきかない語」が苦手なため、
`app/keyword_search.py`にキーワード一致(TF-IDF)検索を追加した。追加ライブラリは不要で、
英数字の連続(例: `CVT-2000`)は1語、日本語は2文字ずつ重ねた単位で索引化する。
次のどちらかの場合に自動で切り替わる(ただしキーワードが1件も一致しなければ意味検索の結果を維持):

- 意味検索の最高スコアが「該当なし」の水準に満たない
- 検索語に型番らしい英数字(英字と数字の混在)が含まれる

切替時は画面に注記を表示し、各結果に`mode`(`semantic`/`keyword`)を付ける。キーワード検索の
スコアは意味検索とは分布が違うため、閾値を別に持つ(`SearchPolicy`をv2に更新、v1は残置)。

閾値の根拠(v3、2026-09-21実測): 関連する質問12件の最高スコアは0.55〜0.78、無関係な質問10件は
最大0.37。そこで「該当あり」の境界を0.45(A≥0.65 / B≥0.55 / C≥0.45)にした。データや
モデルを変えたときは、同様に関連/無関係な質問で分布を測り直して調整する。
